# Логическая и физическая модель БД пекарни

Диаграммы: `database-logical.svg` и `database-physical.svg`. Фактическая схема нового проекта — `server/schema.sql`; для обновления старой базы — `docs/migration_v2.sql`.

## Сущности и связи

| Сущность | Основные атрибуты | Назначение |
|---|---|---|
| access_rights | id, name | Разделение USER и ADMIN в модели прав |
| users | id, access_right_id, phone, password_hash | Аккаунты покупателей |
| admins | id, login, password_hash | Вход сотрудников в панель |
| categories | id, name | Категории выпечки |
| products | id, category_id, name, description, ingredients, allergens, price, weight_g, prep_minutes, available, image_path | Товары |
| shopping_cart | user_id, product_id, quantity | Корзина вошедшего покупателя |
| orders | id, code, user_id, staff_id, customer_name, phone, pickup_at, fulfillment, delivery_address, status, total, created_at | Заказы |
| order_items | id, order_id, product_id, quantity, unit_price | Позиции заказа и цена на момент оформления |
| positions | id, name | Должности персонала |
| staff | id, position_id, full_name, address, phone, birth_date | Ответственные за заказы сотрудники |
| feedback | id, name, phone, message, created_at | Сообщения покупателей |
| password_resets | user_id, token_hash, expires_at | Одноразовое восстановление пароля |

Связи: категория 1:N товары; пользователь 1:N заказы и 1:N строки корзины; товар 1:N строки корзины и позиции заказа; заказ 1:N позиции; должность 1:N сотрудники; сотрудник 1:N заказы. Для заказа без аккаунта `orders.user_id` пустой. Для ещё не назначенного заказа `staff_id` пустой.

## Нормализация

1НФ: поля содержат скалярные значения; позиции заказа и корзины находятся в отдельных таблицах. 2НФ: в таблицах с простым ключом не бывает частичной зависимости; в `shopping_cart` количество зависит от пары `(user_id,product_id)`. 3НФ: категории, должности и права вынесены в справочники, а не повторяются как зависимые описания. `unit_price` сохраняется отдельно от текущей цены товара, чтобы история заказа не менялась. `orders.total` сознательно дублирует вычисляемую сумму и записывается вместе с позициями в одной транзакции.

В `products.category` оставлено исходное текстовое поле для совместимости со старой версией; источником категории в новых запросах служит `category_id`. После проверки миграции текстовое поле можно удалить отдельной миграцией.

## Логическая и физическая структура

PK — `id` у большинства сущностей; составной PK у `shopping_cart`. FK указаны на диаграммах и в SQL. Уникальны телефон покупателя, логин администратора, код заказа и имена справочников. Типы данных видны в физической диаграмме и `server/schema.sql`. Ограничения длины, количества от 1 до 20 и допустимых статусов дополнительно проверяются в PHP.

Представление `catalog_view` объединяет товары и категории. Представление `sales_report` объединяет заказы, позиции и ответственных сотрудников. Пять выборок по образцу задания находятся в `docs/queries.sql`.
