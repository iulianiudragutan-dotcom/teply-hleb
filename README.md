# Тёплый хлеб — учебный веб-ресурс пекарни

PHP 8.1+, MySQL/MariaDB, HTML, CSS и JavaScript. Покупатель может просмотреть ассортимент, зарегистрироваться или оформить заказ без аккаунта, выбрать самовывоз или доставку, проверить статус. Сотрудник управляет товарами, фотографиями, заказами, персоналом, сообщениями и отчётом.

## Установка с нуля

1. Поместите папку `teply-hleb` в корень PHP-сайта.
2. Один раз импортируйте `server/schema.sql` в MySQL/MariaDB. Повторный импорт добавит демонстрационные товары повторно.
3. Скопируйте `server/config.example.php` в `server/config.php` и настройте `DB_DSN`, `DB_USER`, `DB_PASSWORD` в окружении PHP. Пример DSN: `mysql:host=127.0.0.1;dbname=teply_hleb;charset=utf8mb4`.
4. Проверьте расширения `pdo_mysql`, `mbstring`, `fileinfo`, работу сессий и право записи веб-сервера в `uploads`.
5. Создайте учётную запись сотрудника из терминала: `php server/create_admin.php ЛОГИН ПАРОЛЬ_ОТ_12_СИМВОЛОВ`.
6. Откройте `/`, `/account.php`, `/about.php`, `/promotions.php`, `/news.php`, `/contact.php`, `/admin.php`.

## Обновление существующей версии

Сначала создайте резервную копию файлов и БД. **Не импортируйте `server/schema.sql` в действующую базу.** Один раз выполните `docs/migration_v2.sql`; она добавит таблицы покупателей, справочников, корзины, персонала, поля доставки и представления, сохранив текущие товары и заказы. Затем обновите файлы проекта, не заменяя действующий `server/config.php` и папку `uploads`. Скрипт `scripts/deploy-update.sh` делает резервную копию файлов и сохраняет эти два пути.

## Основные сценарии

- Покупатель: каталог → поиск или категория → корзина → самовывоз/доставка → номер заказа → проверка статуса.
- Аккаунт покупателя: регистрация по телефону → вход → корзина в БД → история заказов. Заказ без аккаунта остаётся доступен.
- Восстановление пароля: сотрудник после проверки личности выдаёт одноразовый код на 15 минут; покупатель вводит его в личном кабинете. Автоматическая SMS-рассылка не подключена.
- Сотрудник: вход → обработка заказа → назначение ответственного → изменение статуса → управление товарами и фотографиями → отчёт из SQL-представления.
- Обратная связь: сообщение сохраняется в БД и видно сотруднику.

Сумма заказа считается на сервере по актуальным ценам; количество одного товара ограничено 20. Время получения допускается от 30 минут до 14 дней. SQL с пользовательскими значениями выполняется через подготовленные запросы. Загрузка фото ограничена 2 МБ и форматами JPEG, PNG, WebP.

## Структура проекта и отчётность

- `server/schema.sql` — установка новой БД; `docs/migration_v2.sql` — обновление старой БД; `docs/queries.sql` — пять запросов из серверного приложения.
- `docs/01-domain-analysis.md` — анализ предметной области; `02-business-processes.md` и `idef0-*.svg` — бизнес-процессы; `03-interface-design.md` и `moodboard.svg` — интерфейс; `04-database-design.md` и `database-*.svg` — БД; `05-verification-results.md` и `test-plan.md` — проверки.
- `assets/` — фотографии и значки; `uploads/` — загруженные сотрудником изображения. Снимки рабочего сайта хранятся локально и в публичный репозиторий не включены.
- `account.php`, `account.js`, `account.css` — личный кабинет; `admin.php`, `admin.js` — панель сотрудника; `server/api.php` — серверные сценарии; `server/customer_helpers.php` — функции аккаунта, сохраняемые при обновлении конфигурации.

Репозиторий GitHub хранит исходный код и документацию. GitHub Pages не исполняет PHP/MySQL, поэтому работающий сайт должен размещаться на PHP-сервере. В публичный репозиторий не добавляйте действующий `server/config.php`, загруженные фотографии с личными данными, дамп с заказами или пароли. Для эксплуатации с реальными данными нужны HTTPS, действительные контакты и правила обработки заказов; в учебном проекте адреса демонстрационные.
